# Отчёт по Лабораторной работе №5
**"Технический долг. Устранение долга"**

---

## 1. Введение

Технический долг в рамках данного проекта (информационная система поиска стран) рассматривается как осознанный компромисс для обеспечения высокой скорости поставки базового функционала. На текущем этапе кодовая база (FastAPI + React) характеризуется высокой расширяемостью, что позволяет внедрять сложные интеграции (внешние API, визуализация) без радикальной переработки ядра.

Цель работы - инспекция текущего состояния проекта, приоритизация задач по рефакторингу и обоснование того, что накопленный долг является "здоровым" и не препятствует развитию продукта в 3-м спринте.

---

## 2. Инспекция проекта на наличие технического долга

### 2.1. Непонятный / нечитабельный код
**Наличие:** Практически отсутствует.

Использование FastAPI и Pydantic на бэкенде обеспечивает строгую типизацию и самодокументируемость. На фронтенде компоненты разделены по функциональному признаку.
**Замечание:** Логика в `GetCountry.js` требует декомпозиции, так как планируемое добавление блоков погоды и времени может перегрузить компонент.

### 2.2. Дублирующийся код
**Наличие:** Незначительное.

Основные повторы связаны с обработкой JWT-токенов в каждом сетевом запросе. Требуется внедрение централизованного Axios-инстанса или API-клиента для унификации заголовков.

### 2.3. Отсутствие автоматизации (тестов, сборки, развёртывания)
**Наличие:** Частичное.

Проект стабильно работает в dev-окружении. Отсутствие Unit-тестов компенсируется строгой валидацией схем на бэкенде. Автоматизация деплоя запланирована на финальную стадию.

### 2.4. Запутанная архитектура и ненужные сложные зависимости
**Наличие:** Отсутствует.

Архитектура прозрачна: роутеры -> модели -> схемы. Внешние зависимости (MUI, SQLAlchemy) используются по назначению без избыточного усложнения.

### 2.5. Медленные / неэффективные средства
**Наличие:** Отсутствует.

Async/await модель FastAPI и легковесная SQLite обеспечивают минимальный Time to First Byte (TTFB).

## 4. Оценка плана мероприятий

Общий объем работ по ликвидации долга оценивается в **13 часов**.
- Это время распределено между двумя разработчиками и не требует остановки работ над новыми фичами.
- Приоритет отдан задачам, которые упростят внедрение интеграций в 3-м спринте (пункты 1 и 4).

---

## 5. Сравнение объёма долга и недоимплементированных фич

На 3-й спринт запланирован значительный объем работ по улучшению UI и расширению функционала за счет внешних данных:

| Тип задачи          | Описание фичи                                                               | Оценка (ч) |
|---------------------|-----------------------------------------------------------------------------|---|
| **API Integration** | Интеграция с Global REST Countries API (кэширование, проксирование данных)  | 8 |
| **Country Map**     | Визуализация расположения страны относительно других стран                  | 6 |
| **Frontend UI**     | Вывод флагов (иконки в списках, крупные изображения в деталях)              | 3 |
| **Smart Forms**     | Кнопка "Import from Global API" для автозаполнения формы добавления страны  | 3 |
| **Live Widgets**    | Блок "Current Status" (реальное время и погода в столице через OpenWeather) | 4 |

**Суммарный объём новых фич:** ~24 часа.
**Суммарный объём технического долга:** ~13 часов.
**Соотношение:** Технический долг составляет **~54%** от объёма новых задач.

Такое соотношение является оптимальным: проект сохраняет высокую скорость разработки (Velocity), а время на рефакторинг органично вписано в процесс внедрения новых визуальных элементов.

## 6. Выводы и обоснование необходимости устранения долга

### Состояние проекта
Технический долг в проекте находится на контролируемом, низком уровне. Текущая структура позволяет беспрепятственно внедрять внешние интеграции и улучшать визуальную составляющую приложения.

### Обоснование стратегии
Полная остановка разработки ради рефакторинга признана нецелесообразной. Выбрана стратегия **"Инкрементального улучшения"**:
1. Рефакторинг API-запросов будет проведен одновременно с внедрением логики "Import from Global API".
2. Документация и тесты будут расширяться параллельно с созданием виджетов "Current Status".

**Общий вывод:** Проект готов к масштабированию. Выявленный долг не является блокирующим и будет планомерно сокращен в рамках задач 3-го спринта, что позволит выпустить качественный продукт с богатым пользовательским интерфейсом и актуальными данными.
